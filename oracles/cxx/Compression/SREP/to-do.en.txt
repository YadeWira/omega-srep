Extremely fast algorithm (with bitarr, without content-based champions selection):
  1. update crc32c (509 bytes) by 4/8/16 bytes (crc32c+3*clmul/8 bytes), prefetch from bitarr, remember crc32c via xmm: everything takes 1-2 cycles
  2. in the next cycle check the byte from bitarr, on success compute a rolling 64-bit hash2(512 bytes) and do 4-8-16 lookups from hasharr (apparently crc64):
         about a billion hits = hashing 512 GB = 20-30 seconds per 100 GB file, i.e. 1 cycle/1 byte of the file
  3. in the next cycle (?) compare hashes from hasharr with the high words of the corresponding hash2, on success register a conditional match and find its conditional length by hash2
  4. for the final match check, instead of sha1 — aes-based hashing (0.5 sec/GB for calc+check, and everything is in the I/O thread)

Problems of anchor hashing: the offsets at which the anchor triggers are unpredictable, so the hashed blocks must either overlap or there will be
  gaps between them. Further, SHA1 must be stored either from the hashed blocks (causing the same overlaps or gaps), or their boundaries will not coincide
  with the boundaries of the hashed blocks, as a result of which it will be impossible to verify that a hashed anchor block matches an old one. Probably the second option is preferable,
  since matches should not be exactly L bytes, usually they continue a bit longer in both directions.

Anchor hashing:
  the file is split into fixed 512-byte blocks, from each block the "best" 256 bytes are selected (e.g. with the max hash sum) with an offset relative to the block start
  for each 256-byte block the following are stored: chunk (4 bytes) + hash256 (4 bytes) + offset (2-4 bytes) + hash512 (2-4 bytes)
  when scanning the file, the "best" is chosen out of every 64-256 positions, similar blocks are searched by hash256, which are fully matched by hash512

Semi-anchor hashing:
  Take K sub-blocks of a block of length L, each of length L-K+1. Select C largest of them, or all satisfying some condition (lb(K) high bits are 0, etc.).
  Put them into bitarr. When searching, check via bitarr only blocks of length l-K+1 that satisfy the same condition.
  For example, out of 32 sub-blocks of length L-31 put one with the highest hash sum. When searching, choose one with the highest sum out of every 16 blocks of length L-31 and search bitarr only for it.
  The absence of its mark in bitarr guarantees (?) the absence of a match (since the max of 16 aligned blocks must include the max of 32 unaligned ones).
Clarification:
  Take K sub-blocks and compute their hashes. Find the max of the first K/2 hashes, then of the next K/2 hashes, etc. — K/2+1 values in total, most of which will coincide.
  Mark them in bitarr.
  When scanning the file, find the max of every K/2 hashes and check only it via bitarr.
Alternatively:
  Insert into bitarr the maximum hash of K of length L-K+1.
  In the file, compute the max hash of the last K and look for it in bitarr.

Ideal compressing algorithm for -m3..5: ========================================================================================================================
  hash1 = crc<size_t> of L-N+1 bytes for checking bitarr[]
  hash2 = crc64 of N bytes for checking chunkarr/hasharr (32-bit index into chunkarr + 32-bit value stored in hasharr)
  for each L-byte block
    // Part 1: prefetch bitarr[]
    for (i=0; i<L-N; i+=N)
      prefetch bitarr[hash1]
      *hash1p++ = hash1
      for (j=0; j<N; j++)
        hash1.update()
        *hash2p++ = hash2
        hash2.update()      // store hash2 in case of a successful bitarr[] probe

    i=L-N
      for (j=0; j<N; j++)
        prefetch bitarr[hash1]
        *hash1p++ = hash1    // store hash1 for the bitarr[] update
        hash1.update()
        *hash2p++ = hash2
        hash2.update()

    // Part 2: check bitarr[] & prefetch chunkarr[]
    for (i=0; i<L; i+=N)
      hash1 = *hash1p++
      if bitarr[hash1]
        for (j=0; j<N; j++)
          hash2 = *hash2p++
          *cptr++ = hash2
          prefetch chunkarr[hash2]

    // Part 3: update bitarr[]
    for (i=L-N; i<L; i++)
      bitarr[hash1] = 1
      hash1 = *hash1p++

    // Part 4: check chunkarr[] — ideally, it should check the data prefetched in the previous block in order to completely hide any memory delays
    for (*p=cbuf; p<cptr; p++)
      hash2 = *p++
      if hasharr[chunkarr[hash2]]==hash2
        match found!

    // Part 5: update chunkarr[]
    chunkarr[hash2] = chunk
    hasharr[chunk++] = hash2
